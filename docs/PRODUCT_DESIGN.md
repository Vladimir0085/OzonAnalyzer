# Проектирование OZ Price Analyzer

## Что показал анализ исходных отчетов

Проверены отчеты по начислениям за март–июль 2026 года, два `RealizationReportCIS`, отдельный отчет по компенсациям, снятый «Отчет по товарам» и итоговая книга с макросом v11.

В пяти неповторяющихся отчетах по начислениям найдено 32 302 строки и 33 фактических типа начисления. Большинство строк содержат артикул, но принадлежность зависит именно от строки, а не от названия типа. Это особенно важно для двух смешанных типов:

| Тип | С артикулом | Без артикула | Правило приложения |
|---|---:|---:|---|
| Обеспечение материалами для упаковки товара | 54 | 4 | товар / «Разбивка» по каждой строке |
| Упаковка товара партнерами | 54 | 4 | товар / «Разбивка» по каждой строке |

Тип начисления нельзя навсегда пометить только как «по артикулу» или только как «нераспределенный»: в следующем месяце фактическое заполнение может измениться. Поэтому справочник показывает наблюдаемое распределение отдельно для выбранного расчета и для всей истории.

В июльском отчете контрольная сумма начислений без артикула равна `−25 050,00 ₽`:

| Тип | Строк | Сумма, ₽ |
|---|---:|---:|
| Перенос карточек товаров | 1 | −15 000,00 |
| Подписка Premium | 1 | −9 990,00 |
| Упаковка товара партнерами | 4 | −40,00 |
| Обеспечение материалами для упаковки товара | 4 | −20,00 |
| Итого | 10 | −25 050,00 |

Компенсации уже присутствуют в отчетах по начислениям. Отдельный `CompensationReport` создает риск повторного учета и не принимается. Компенсация с артикулом попадает в столбец «Компенсации Ozon», без артикула — в «Разбивку».

Корректный `RealizationReportCIS-12439885000000.xlsx` содержит 5 строк, 8 единиц и 1 613,68 ₽. `RealizationReportCIS-124398851.xlsx` не проходит арифметическую проверку: в одной из строк итог не равен цене реализации, умноженной на количество. Такой файл нельзя молча включать в расчет.

## Предлагаемая структура интерфейса

Основной принцип — сначала показать результат и проблемы, затем дать доступ к деталям.

| Вкладка | Назначение |
|---|---|
| Обзор | Общие KPI отчета, отдельные KPI выбранной категории, фильтр/поиск/сортировка и полный построчный результат v11 |
| Исходные файлы | Состав расчета, хэш, период и просмотр любого листа без Excel |
| Разбивка | Все начисления без артикула по типам, количество строк и сумма |
| Справочник начислений | Категория результата и фактическое распределение: текущий запуск / история |
| Сценарий цены | Плановая цена, категория, фильтр/поиск/сортировка, массовое изменение и прогноз прибыли |
| История отчетов | Снимки периодов и журнал контроля качества |
| Справка | Обязательные и дополнительные отчеты Ozon, пути скачивания и расшифровка всех показателей «Обзора» |
| Настройки | Тема, налог, дубли, предупреждения, основной редактор товаров и себестоимости |

Темная тема используется по умолчанию, а режим «Системная» читает настройку приложений Windows. Светлая тема доступна вручную. Используются Segoe UI, плоские карточки, спокойный фон, один акцентный цвет и цвет только для смысловых статусов.

При чистой установке справочник себестоимости пуст. Первичное заполнение выполняется из проверяемого XLSX со столбцами «Артикул», «Наименование», «Категория», «Полная себестоимость» и «Трудозатраты». Затем пользователь видит товары в одной таблице, может искать по артикулу, наименованию и категории, отбирать активные и архивные позиции, добавлять товары и редактировать их прямо в приложении. Материальная часть рассчитывается автоматически. Перед записью показывается сравнение старых и новых значений, а после записи изменения попадают в журнал. Полная очистка каталога требует отдельного подтверждения и не удаляет сохраненные отчеты.

Итоги выбранной категории рассчитываются только по товарным строкам. Они включают выручку, чистую прибыль, доходность, количество продаж, себестоимость проданного и финансовый результат Ozon. Нераспределенные начисления не имеют товарной категории и в этот блок не входят. Поиск по артикулу и сортировка меняют только отображение строк, но не сумму выбранной категории.

## Контроли, которые нельзя убирать

- SHA-256 и предупреждение о повторной загрузке — защита от двойного учета;
- снимок себестоимости внутри каждого расчета — изменение стоимости не переписывает числовую историю; текущая категория как классификационный признак обновляется во всех периодах;
- проверка обязательных заголовков — изменение формата Ozon не должно давать тихо неверный результат;
- проверка строк и итога `RealizationReportCIS`;
- запрет отдельного `CompensationReport`;
- предупреждение об отсутствии `RealizationReportCIS`;
- предупреждение о конфликте одного SKU с несколькими артикулами;
- явное решение по каждому новому артикулу;
- сверка суммы вкладки «Разбивка» с нераспределенным итогом;
- неизмененная копия исходного файла для воспроизводимости;
- проверяемая резервная копия базы и исходников перед переносом или восстановлением.

## Сценарий плановой цены

Расчет перенесен из столбцов AL–AY книги v11. Объем продаж остается текущим. Средняя комиссия и доля баллов берутся из выбранного периода. Другие расходы Ozon сохраняются на текущем уровне.

Для товара вычисляются:

1. текущая средняя цена и изменение плановой цены;
2. плановая выручка при текущем объеме;
3. плановая комиссия и баллы по средним долям периода;
4. налогооблагаемая база и налог;
5. прибыль до себестоимости, чистая прибыль на единицу и доходность.

Это сценарий, а не прогноз спроса: приложение явно сообщает, что изменение цены не меняет количество продаж.

## Что разумно добавить следующим этапом

1. Добавление сертификата издателя в секреты репозитория: автоматическая Windows-сборка уже умеет подписывать и проверять EXE при наличии сертификата.
2. Автоматическая проверка обновлений после стабилизации формата Ozon и появления постоянных релизов.

Сравнение периодов, графики динамики, управление себестоимостью и безопасный перенос всей истории уже реализованы в первой рабочей ветке приложения.

До этих функций важнее накопить несколько реальных периодов в новой базе: это даст надежные требования для сравнения и графиков без усложнения первого рабочего интерфейса.
